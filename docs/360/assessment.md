# 케이프혼타워 360° — 조사 및 기술 검증 보고서

2026-10-15. 기준: wing-kim/all `0f250ee`, v87. 판정: **연속 3D 조작 검증 통과 / 기존 실사 수준의 시각적 품질 미달 / 최종 구현 미완료**.

사용자 보완 지시: 실사 모드의 AI 이미지를 시각적 기준으로 사용하되, 부정확하거나 충돌하는 형태는 기존 스케치업·렌더를 우선한다. 따라서 사진과 다른 코어 벽, 층고, 옥상 등을 사진에 맞춰 임의로 변경하지 않았다.

## 2. 최고 품질 이미지의 위치와 표시/생성 방식

시각적 최고 품질 계열은 본체의 **실사 모드**다. 기본 올 글라스와 석재 시안의 코너, 올 글라스 측면/후면 이미지를 직접 열어 확인했다. 모든 시안 사이에 객관적인 단일 최고 순위를 매긴 것은 아니다. 이번 대표 기준은 기본 올 글라스 `ext/glass/045.webp`다.

- `kapehorn-media`: catalog.js / catalog.json, thumb와 std WebP.
- `kapehorn-media-hd`: hd WebP. API로 폴더 존재 확인; HD 전체 파일을 내려받아 평가하지는 않았다.
- catalog 버전 `2026-10-14 05:18`, 기준 주차 `alt4`(자주식3).
- 이미지가 있는 외관 시안은 각 0/45/90/135/180/225/270도, 7장이다. 315도가 없고 마지막 간격은 90도다. `r360:true`는 연속 재구성의 증거가 아니다.
- `PH` 코드가 상대경로 저장소 → 공개 Pages → legacy render 폴더 순으로 목록을 찾는다. thumb → std → 화면 조건에 따라 hd를 `<img>` 두 개에 번갈아 표시한다. 드래그 70px마다 다음 사진으로 이동한다.
- 사용자 확인에 따라 AI 생성 이미지 모음이다. 저장소에는 생성 모델명, 프롬프트, 시드, 원본 카메라·깊이·메시가 없다. README의 `디자인 설계/05_웹용/변환.bat`는 웹용 변환 파이프라인 언급이며 AI 생성 절차 자체는 확인할 수 없다.
- 다른 외장 디자인의 사진을 한 장면의 다중 시점으로 섞으면 안 된다.

실사 품질의 원인은 도구 이름보다 그림에 포함된 정보량이다. 실내 가구·식물의 깊이, 창호의 가는 프레임, 유리의 반사와 투과, 외장재의 미세한 표면 변화, 나뭇잎과 접촉 그림자, 거친 아스팔트와 포장 이음새, 높은 밀도의 도시 배경, 자연스러운 노출이 동시에 있다. 기존 3D에는 그 중 상당수가 단순화되거나 생략돼 있다.

사진의 구조는 확정 설계 근거로 삼지 않는다. 예를 들어 후면 AI 이미지는 기존 모델의 막힌 코어 벽 일부까지 유리로 표현한다. 옥상 퍼걸러·태양광 표현도 서로 다르다. 카메라 캘리브레이션이 없어 동일 카메라를 정확히 재현했다는 주장은 할 수 없으며 이번 비교는 근사 구도다.

## 3. 재사용 자료와 정확도

기존 모델은 별도의 SKP 파일을 로드하는 것이 아니다. ‘스케치업’이라는 UI 이름을 가진 Three.js 절차형 모델이다. `S=41.6, OX=914, OY=770` 좌표 변환, SITE 다각형, 층별 평면/코어/램프/창호, 높이/주차 대안이 코드에 있다. 대지 749㎡, 기본 지상 6층, 1층 5.4m, 기준층 4.2m, 최고 34.2m/옥탑 약36.6m 등이 모델에 표시된다. **원본 도면을 새로 측정해 검증한 값이 아니라 기존 코드의 값**이다. 코드도 이미지 판독 오차 약 ±0.5m를 명시한다.

주변 건물은 기존 설명상 지도·거리뷰에 근거한 위치/높이 근사 모델이다. 신축 모드의 건너편 미성아파트 고층은 현황이 아니라 재건축 가정이다. 실제 현황과 신축 시점의 예상 환경을 구분해야 한다.

사이트에 연결된 Drive 설계안 폴더를 읽어 2026-04-29/05-04/05-08 제안서 PDF 4개가 있음을 확인했다. 이 작업에서는 파일 메타데이터까지만 확인했으며, 현재 모델과 같은 버전의 확정 CAD/BIM이라고 확인하지 않았다. 로컬 작업 폴더와 all/media 저장소에서는 프로젝트용 CAD/BIM/SKP/BLEND/GLB 원본을 찾지 못했다. 사용자 지시에 따라 기존 모델이 현 단계 구조 기준이다.

| 분류 | 내용 |
|---|---|
| 바로 재사용 | 기존 단일 3D 형상·층별 파라미터·도로/주변 배치·OrbitControls·원본 실사 이미지·기존 사이트 |
| 기존 자료로 제작 가능 | 동일 형상의 연속 시점, 카메라 프리셋, 일반 PBR 재질 연구, 반사/노출 조정, 비교 페이지 |
| 추가 자료로 정확도 향상 | 창호 단면/프레임 폭, 마감재 샘플, 고해상도 현장 거리 사진, 위치 정합 HDRI, 실제 식재 종류 |
| 반드시 확인할 것 | 실물 정확도를 보증하려면 최신 도면 버전, 후면/옥상 확정 구성, 실제 주변 현황과 재건축 가정 중 대상 시점 |
| 새로 제작할 자산 | 정리된 UV/법선/모서리 베벨, 실제 스케일 PBR 세트, 실내 깊이 요소, 상세 주변 건물/수목, 베이크 조명 |

## 4. 기술 비교와 선택

아래 평가는 이 프로젝트 입력 자료에 대한 판단이며 각 기술의 보편적인 성능 순위가 아니다.

| 방식 | 사진 수준 잠재력 / 설계 정확도 | 연속 360 / 보이지 않는 면 | 자동화와 수정 |
|---|---|---|---|
| UE5 + Pixel Streaming | 매우 높음 / 정확한 원본 모델이 있어야 높음 | 가능 / 별도 모델링 필요 | Python·에디터 자동화 가능, 에셋 제작 부담 큼 |
| Three.js WebGL/WebGPU | 고품질 에셋·조명 전제 / 형상 통제 우수 | 가능 / 도면·기존 모델로 작성 | 코드·glTF 파이프라인 자동화 우수 |
| Blender Cycles 제작 + 웹 베이크 | 기준 렌더는 매우 높음 / 치수 통제 우수 | 웹에서는 별도 실시간 뷰어 필요 / 모델링 | Python·CLI 렌더·베이크 자동화 가능 |
| 3D Gaussian Splatting | 정합 촬영 데이터에서 높음 / 치수·편집 제약 | 관측 범위에서는 가능 / 미관측은 보장 불가 | 학습 자동화 가능, 국소 구조 수정 불편 |
| NeRF / Instant-NGP | 적절한 촬영 데이터에서 높음 / 측정 정확도 별도 검증 | 가능하나 관측 외 외삽 취약 / 추가 촬영 | GPU 학습·배포 절차 필요 |
| Multi-view / COLMAP + 메시 | 입력 정합성이 중요 / 보정·스케일 기준 필요 | 메시 생성 후 가능 / 미관측 면 모델링 | SfM·MVS 자동화, 반사 유리·반복 창호 어려움 |
| Image-based rendering / 투영 텍스처 | 가까운 원본 각도에서 좋음 / 깊이 부정확 가능 | 시차·가림 해제에서 늘어짐 / 별도 깊이·모델 | 자동 투영 가능, 이음새·구운 조명 수정 필요 |
| 정확한 메시 + PBR/베이크 + 선택적 재구성 환경 | 이 자료에서 가장 통제 가능한 경로 / 단일 구조 유지 | 가능 / 모델 기준으로 일관되게 제작 | 건물·재질·환경을 독립 검증 가능 |

| 방식 | 웹 통합 / 성능 | 추가 자료·비용 | 예상 한계 |
|---|---|---|---|
| UE5 streaming | 브라우저 프런트엔드 + GPU 서버, Pages만으로 불가 | 상세 에셋, GPU 서버·동시 접속 운영비 | 네트워크 지연, 서버 가용성·세션 비용 |
| Three.js | 정적 Pages 가능, 장치 GPU에 의존 | 정리된 모델·PBR·LOD, 에셋 제작 시간 | 대규모 투명 유리/그림자/후처리 비용 |
| Blender + baked glTF | Pages 가능, 베이크 후 비교적 가벼움 | UV·베이크 제작, 오프라인 렌더 시간 | 시간대 변화 시 baked lighting 한계, 반사는 별도 처리 |
| 3DGS | 전용 웹 렌더러 가능, splat 수/메모리에 의존 | 정합 다중 시점·학습 GPU | AI 이미지 모음에서 부유물·구조 붕괴 위험 |
| NeRF | 별도 런타임/변환 필요, 학습 및 추론 비용 | 보정 영상·GPU | 모바일 실행·편집·외삽 어려움 |
| MVS | 결과 메시 웹 최적화 필요 | 겹침 촬영, 치수 기준, 정리 작업 | 유리·균일면·미관측 표면 복원 실패 |
| IBR | 정적 웹 가능, 가볍게 시작 가능 | 정확한 깊이/카메라와 배경 보완 | 자유 시점에서 텍스처 늘어짐·이중상 |
| 하이브리드 | 정적 기본 뷰어 + 필요 시 고사양 별도 | 건물 형상 재사용, 환경/재질 신규 제작 | 에셋 품질 확보 작업을 생략할 수 없음 |

**권장 생산 경로:** 기존 형상 → GLB 추출 → Blender 등 DCC에서 법선/중복면/베벨/UV 및 재질 정리 → 고품질 기준 렌더와 원본 비교 → 간접광/AO 베이크·LOD 최적화 → 웹 실시간 뷰어. 주변 환경은 현장 자료가 있을 때 별도 photogrammetry/3DGS 활용 가능. 건물 자체는 AI 이미지로 학습하지 않는다.

**이번에 실제 검증한 경로:** 기존 r128을 유지한 Three.js WebGL + HDRI/PBR 보정. WebGPU 전환은 에셋 부족을 해결하지 않으며 기존 r128 재질·후처리 전체의 마이그레이션이 필요해 첫 검증에서 제외했다. Blender/UE/GS/NeRF 학습을 실행한 것은 아니다.

비용: 이번 작업에 유료 서비스·추가 결제를 사용하지 않았다. Three.js MIT, HDRI CC0. 본 제작의 주 비용은 건물/주변 환경 에셋 제작과 검수 시간이다. UE 서버 비용은 GPU·지역·동시 접속·가동 시간 미정으로 확정 견적 불가. 사용 승인 전에는 도입하지 않는다. 일정·금액을 근거 없이 확정하지 않는다.

## 5. 구현 범위

`new/360/index.html`에 별도 비교 뷰어를 추가했다. 기존 본체에는 `?lab=360`일 때만 동작하는 연결 지점 9줄을 추가했다. 기본 스케치업/렌더/실사 설정과 기존 이미지 자산은 변경하지 않았다. 최종 품질 검증이 실패했으므로 메인 메뉴의 정식 기능 교체·통합 및 main 배포는 하지 않는다.

- 단일 3D 장면의 수평 자유 회전, 수직 회전, 휠 확대/축소, 건물 중심 고정.
- 코너/조감/정면/후면/좌/우 프리셋, 원호 카메라 이동, 자동 회전.
- 원본 실사 비교 패널. 비교 이미지의 버튼별 전환은 참고 패널에만 있으며 3D 장면은 이미지 전환이 아니다.
- 기존 alt4/올 글라스 형상, HDR 반사, 유리 roughness/metalness/opacity 조정, 미세 표면 요철, 고정 시드 식재·가구 표현 실험.
- 균형/고품질 선택, 오전/오후/일몰 조명 연구. 실제 날짜의 태양 위치를 보증하는 기능은 아니다.
- 형상 GLB 저장. 모델의 질감·환경을 완전히 이식하는 export가 아니라 형상 전달용이며 재질은 기본값으로 단순화한다.
- 원본과 프로토타입은 외부 폴더/파일을 수정하지 않고 별도 구현.

| 카메라 경로 | 각 전환에서 건물 중심까지 약79m 유지. 건물 관통하는 직선 보간을 원호로 수정. 주변 건물 충돌 회피는 미구현 |

| 실사 품질 | **미달**. 기존 실사에 근접했다고 판정하지 않음 |

첫 렌더의 큰 그림자 줄무늬는 도시 전체용 shadow frustum을 건물 주변으로 좁혀 줄였다. 여전히 먼 도로의 잔여 줄무늬·단순 재질, 창호/반사의 반짝임, 유리 겹침 표현 문제가 보인다. 가구·식재를 더해도 주변 건물의 기하·텍스처 밀도와 간접광이 부족하다. 후면 코어는 의도적으로 기존 형상 유지. 배경 HDRI는 반사용 일반 도시 자료이며 실제 신사동을 재현한 것이 아니다.

따라서 기술적인 360 조작 성공과 사실감 성공은 다르다. 엔진 교체나 노출 조절만으로 이 간극을 해결했다고 보고할 수 없다. 기존 실사 이미지와 픽셀 차이를 수치화해 품질 점수로 만들지 않았다. AI 이미지의 형상·카메라가 달라 해당 점수가 정확도를 오히려 왜곡하기 때문이다.

## 7. 실행 및 GitHub 반영

작업 브랜치: `codex/tower-360-validation`. draft PR로 검토 가능하게 보관하며 main은 변경하지 않는다. 최종 사이트 배포 완료라고 보고하지 않는다.

python3 -m http.server 8765 --bind 127.0.0.1

## 8. 다음 품질 게이트

1. GLB를 제작 도구에 가져와 중복면·법선·유리 정렬을 정리하고 창호에 실치수 베벨/실링/프레임 깊이를 준다. 원본 모델의 외곽과 개구부 위치를 기준으로 차이를 검수한다.
2. 유리 뒤 실내를 깊이가 있는 공간으로 구성하고 PBR 텍스처를 실제 단위로 작성한다. 한 장의 AI 이미지를 전 입면에 붙이지 않는다.
3. 반경 100~200m의 주변 건물과 도로/수목을 현장 근거로 고도화한다. 미성 재건축 가정은 별도 상태로 분리한다.
4. 고품질 기준 렌더를 동일 근사 카메라 0/45/90/180/270도와 중간 각도에서 비교한다. 구조 변경 0건, 중간 각도의 늘어짐/이중상 0건, 유리/수목/지면 품질을 모두 검수한다.
5. 적절한 베이크·LOD·텍스처 압축을 적용한 웹 결과를 데스크톱/모바일에서 재검증한다. 대표 장치에서 30 FPS 이상을 목표로 하되 품질을 임의로 낮춰 통과 처리하지 않는다.
6. 시각적 게이트를 통과한 뒤 기존 사이트에 링크를 추가하고 공개 배포한다. 실패한 현재 시제품을 최종 결과로 대체하지 않는다.
