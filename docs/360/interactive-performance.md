# 실시간 탐색과 수동 정밀 렌더 분리 — 2026-10-16

실행: `http://127.0.0.1:8765/new/3d-model.html?lab=review`

전후 화면: [interactive-comparison.html](interactive-comparison.html)

## 변경

- 기본 **실시간 360°**는 환경 반사, 각도에 따른 유리 반사, 투명한 실내, 그림자와 GTAO 접촉 음영을 사용한다. 카메라가 멈춰도 광선 추적을 자동 시작하지 않는다. 정지 화면은 다시 그리지 않아 유휴 GPU 사용을 줄인다.
- **정밀 이미지 만들기**를 눌렀을 때만 패스 트레이서/BVH/노이즈 제거 기능을 준비한다. 계산/완료 중 회전, 재질/시안 변경, 조명 변경 또는 **탐색으로 돌아가기**를 누르면 실시간 탐색으로 돌아간다. 정밀 모드는 여전히 계산 시간이 필요하다.
- Three.js 공통 모듈과 정밀 모듈을 분리했다. 기본 진입에는 정밀 모듈과 OIDN 가중치를 요청하지 않는다. 기본 WebGPU 경로에서 사용하지 않던 WebGL HDR 2개와 반사 캡처 준비를 생략한다. 호환 경로는 보존했다.
- 식재·차량·가구를 병렬로 불러오고, 디코딩한 템플릿과 텍스처 이미지를 재사용한다.
- 시안 변경 시 iframe/렌더러/주변 환경을 보존하고 원본 생성 코드로 본 건물과 층에 종속된 가구·블라인드·옥상 식재만 갱신한다. 바뀐 층고에 기존 가구가 떠 있는 문제를 피하도록 배치도 다시 계산한다.
- 원본 실사/스케치업 보기로 갔다가 돌아올 때 3D 화면을 숨겨 보관했다가 재사용한다. 숨겨진 현대 렌더러는 렌더링을 멈춘다.
- 정적 주변 환경의 동일한 불투명 재질과 공간 구획별 메시를 병합한다. 고밀도 스캔 에셋은 공유 기하를 유지하며, 정밀 계산에는 병합 전의 공유 메시를 사용한다. 본 건물은 병합 대상에서 제외한다. 월드 좌표/UV/노멀을 유지하며 병합 전후 실제 정점 경계가 일치하는지 검사한다.
- 원본 `new/3d-model.html`의 설계 생성 로직은 변경하지 않았다. 실험 뷰어가 활성화된 동안에만 불필요한 구형 반사 갱신을 생략한다.

## Chrome 관찰값

같은 Mac, 로컬 Python 서버, Chrome의 기존 브라우저 캐시를 사용한 개발 중 관찰값이다. 엄격한 cold-cache 벤치마크나 기기별 보장값은 아니다. 초기 시간은 통합 페이지가 iframe 준비를 시작한 시점부터이며 부모 HTML 부팅 전체 시간을 뜻하지 않는다.

| 항목 | 이전 | 변경 |
| --- | --- | --- |
| 현대 렌더러 준비 | 22.95초 | 약 14~17초 |
| 최초 고품질 결과 | 77.53초 (자동 64샘플 완료) | 기본은 초기 준비 직후 실시간 결과 표시 |
| 각도 변경 뒤 정밀 완성 | 54.08초 | 기본 탐색에는 누적 렌더 대기 없음 |
| 대표 시안 적용 내부 작업 | iframe 전체 재생성 | 약 0.2~0.8초 (선택 디바운스·첫 셰이더/GPU 표시 시간 별도) |
| 주변 환경 묶음 처리 | 2,743개 렌더 객체 | 1,396개 (1,347개 감소, 기계식 기본 시안) |
| 드래그 평균 프레임 간격 | 변경 중간 버전 약 56ms | 최종 아치 시안 약 33.6ms (~30fps, 이전과 시안이 다름) |

최종 빌드의 별도 관찰에서 카메라 위치 변경 → 두 프레임 → GPU 제출 완료는 0.44초, 직접 조합에서 추천 아치로 두 버튼을 누른 뒤 GPU 표시 완료는 2.31초였다. 첫 재질 셰이더 준비와 UI 처리까지 포함하면 내부 건물 갱신 시간보다 길다.

이전 자동 정밀 이미지와 새 기본 화면은 렌더링 방식과 광학 정확도가 다르다. 78초에서 14초로 같은 정밀 렌더 계산 자체가 빨라졌다는 의미가 아니다. 새 기본 화면은 물리적으로 정확한 다중 유리 반사/굴절을 근사한다. 초기 셰이더 준비 및 무거운 시안에서는 순간적인 지연이 남는다. 60fps를 보장하지 않는다.

## 검증

- 실제 Chrome 마우스 드래그 입력, 별도 정밀 버튼 → 64샘플 완료 → 드래그 시 실시간 복귀 확인.
- 기계식·자주식3, 석재, 추천 아치, 아이보리 색상, 5층/1층 4.8m 변경 후 부모 원본 state와 자식 state, 층별 높이·평면이 일치.
- 변경 전후 동일 iframe/렌더러/주변 환경 객체를 사용함을 확인.
- 실사 보기가 활성화되고, 실시간 복귀 시 동일 렌더러 재사용 확인.
- 광선 추적 없이도 하늘·수목·차량·유리·그림자가 보이는 화면을 직접 확인.
- `test-geometry-copy.mjs`, `test-curtain-wall.mjs`, `test-static-batching.mjs` (월드 삼각형/UV 보존, 고밀도 공유 에셋 제외, 정밀 경로 공유 기하 보존), JS 구문 검사, 번들 빌드, `git diff --check` 통과.
- `interactive-baseline.json`, `interactive-selections.json`, `interactive-lifecycle.json`, `interactive-final-audit.json`은 중간/최종 단계의 실제 관찰 기록이다. 각 스냅샷의 객체 수와 해상도 설정은 개발 단계에 따라 다르다.

최종 검증 중 단순히 주변 메시를 모두 병합하면 정밀 렌더 버퍼가 512 MiB 한도를 넘는 문제를 발견했다. 고밀도 에셋 제외만으로 부족해, 실시간 묶음 메시와 정밀 계산용 공유 메시를 분리했다. 실제 동일 아치 시안에서 64샘플 완료, 드래그 시 실시간 복귀, 해당 실행의 console error 없음까지 재검증했다. 정밀 경로 오류 시 기본 탐색을 유지하도록 처리했다.

## 남은 작업

전체 시간대별 UV 라이트맵 베이킹은 이번에 적용하지 않았다. 현재는 사전 준비한 환경광/반사와 재사용되는 그림자, 실시간 접촉 음영의 조합이다. 추가 개선은 정적인 주변 환경부터 간접광을 베이킹하고, 많은 사용자 조합을 허용하는 본 건물은 검증된 고정 시안부터 확장하는 방식이 적합하다. 유리 반사 전체를 평면 라이트맵으로 대체하지 않는다.

초기 접속은 여전히 빠르다고 할 수준은 아니다. 원본 대형 인라인 엔진과 새 엔진의 중복, 모델 생성/병합, 최초 셰이더 컴파일, 에셋 디코딩 비용이 남아 있다. 이후 개선은 원본 모델 데이터와 UI 분리, 미리 제작한 주변 GLB/압축 텍스처, 모델 작업의 Worker 이동이다. 이번에는 설계 생성 로직을 대규모로 바꾸지 않았다.

모든 20종 추천안과 모든 매스/외장 조합을 전수 검증한 것은 아니다. WebGPU 미지원 기기의 호환 화면과 모바일은 별도 성능 검증이 필요하다. AI 실사 이미지와 동등한 사진 품질을 달성했다고 주장하지 않는다.

최종 사용자용 기본 화면 재접속은 15.45초였다. 이미지 저장 패널에서 실제 1702×922 PNG(빈 화면 아님)를 확인했고 기본 구도로 복원했다.
