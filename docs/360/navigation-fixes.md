# 카메라 조작 및 이전 버전 화면 진단 — 2026-10-16

## 확인한 원인

사용자가 열어 둔 인앱 브라우저에는 `integrated.js?v=review-6`과 자동 64샘플 렌더러가 실행 중이었다. 최신 파일이 디스크에 있어도 이미 실행된 탭의 스크립트가 자동 교체되지는 않는다. 해당 탭을 새로고침했다.

그 탭의 자식 장면에서 `TOWER_LAB_CONTEXT.interior()`가 실제로 true였다. 원본의 외부 건물/바닥 클릭 → `extGo()` → 실내 걷기 기능이 실험 뷰어에서도 작동했다. 이때 회전 중심이 눈앞으로 바뀌며, 휠이 거리 대신 원본 카메라의 FOV를 바꿨다. 현대 렌더 카메라와도 불일치했다. 키보드 이동도 원본에서는 실내에서만 지원했다.

## 수정

- 독립 360도 장면에만 `TOWER_ORBIT_ONLY`를 설정해 클릭으로 실내 걷기에 진입하지 않도록 했다. 원본 스케치업의 내부 보기 기능은 보존한다.
- **건물 전체 보기 ↗** 버튼과 **Home** 키: 공중에서 건물 중심을 보는 시점으로 복귀한다.
- **WASD / 방향키**: 화면 방향을 기준으로 수평 이동. **Q/E**: 아래/위. **Shift**: 빠르게 이동. 입력 필드와 조합 단축키는 가로채지 않는다.
- 캔버스를 클릭하면 키보드 포커스를 받는다. 부모 패널에 포커스가 있는 경우에도 외부 탐색 키를 전달한다.
- 휠 확대 범위를 확장했고, 카메라 이동 버튼의 애니메이션 중 사용자가 직접 조작하면 자동 이동을 취소한다.
- 고품질 기본 화면은 1.25배 해상도에서 렌더한 뒤 FXAA와 축소를 적용한다. 균형 모드는 1배다. 1.5배 실험에서는 비용이 커져 1.25배로 조정했다. 4x MSAA는 현재 GTAO의 깊이 샘플링과 WebGPU 셰이더가 호환되지 않아 채택하지 않았다.
- 재질 준비 전 임시 저품질 화면 대신 준비 상태를 표시한다. 이는 준비 시간이 제거되었다는 뜻이 아니다.

## 베이킹 범위

**UV 라이트맵에 간접광을 베이킹한 상태는 아니다.** 현재는 환경광, 미리 캡처해 재사용하는 반사, 변경 시에만 갱신하는 그림자, 실시간 접촉 음영을 조합한다. 이는 완전한 베이킹과 구분해야 한다.

시안·층수·층고를 바꾸면 그림자와 간접광의 유효성이 달라진다. 시안별 모델/UV/조명 데이터와 무효화 규칙을 먼저 정해야 한다. 그러나 이 사유가 고정된 주변 환경의 베이킹까지 불가능하다는 뜻은 아니다. 고정 주변 환경 → 고정 대표 시안별 간접광 순서로 적용 가능하다. 유리의 시점 의존 반사·굴절은 별도 실시간 표현이 여전히 필요하다.

이번에는 클릭 충돌과 구버전 실행을 실제로 고치고, 기본 화면을 누적 렌더와 분리한 상태를 확인했다. 완전한 베이킹이나 실사와 동등한 품질을 달성했다고 보고하지 않는다.

## 실제 검증

Chrome에서 건물 클릭 후 실내 모드가 false로 유지됨을 확인했다. 실제 휠 입력으로 카메라 반경 79.38 → 75.41m(확대), 다른 테스트에서 79.38 → 83.56m(축소)를 관찰했다. W 입력은 카메라와 회전 중심을 같은 수평 벡터로 이동했고, D/E 입력도 수평/높이 이동으로 반영됐다. 전체 보기 버튼 후 중심은 [-3,16,0]으로 복원됐다.

새 기본 화면은 드래그 후에도 interactive 모드이고 자동 정밀 렌더를 시작하지 않았다. 초기 준비는 한 번의 캐시 사용 관찰에서 14.37초였다. 여전히 최초 모델 생성과 재질 준비 시간이 남아 있다.

세 가지 기하/배칭 회귀 테스트, 번들 빌드, JS 문법 검사를 통과했다. 건물 생성 로직은 변경하지 않았다. 모든 시안·기기에서 깜빡임이 완전히 없음을 보장한 것은 아니다.

최종 고품질 1.25배 빌드 재접속은 15.14초였고, Chrome/인앱 모두 interactive 모드로 확인됐다. 인앱에서 실제 더블클릭·휠 뒤에도 실내 모드 false 및 자주식3 시안 유지, Chrome의 실제 Home 키 입력 후 중심 [-3,16,0] 복귀를 확인했다. 최신 Chrome 실행의 console error는 없었다. `navigation-audit.json`과 `navigation-fixed.png`에 측정/화면을 저장했다. 입력 간격을 포함한 관찰 평균 프레임 간격은 약 57ms로, 60fps를 주장하지 않는다. 저사양에서는 균형 모드를 사용할 수 있다.
