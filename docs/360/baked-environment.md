# 고정 주변 지면 베이킹과 유리 — 2026-10-16 (2026-10-18 외부 완성품 갱신)

## 2026-10-18 갱신 요약

- 원천을 실행 장면에서 다시 추출한다(`TOWER_CINEMA.groundSource()` → `exportGroundSource()`). 주변 건물(context) 불투명 메시 408개, 321,218 삼각형, 본 건물 제외.
- 주변 건물 서명(월드 경계 cm 반올림 + 삼각형 수, 순서 무관 FNV-1a)을 `ground-bake.json`에 기록하고, 실행 시 다르면 베이크를 쓰지 않고 실시간 조명으로 둔다(`status().bake.reason`=`context-mismatch`).
- 외벽 하부: 지면 하늘 가림을 벽 바깥 1.5 m에서 읽어 높이 10 m까지 줄여 가며 aoNode로 적용(강도 0.6, 외벽 335 바인딩). 외벽 자체를 굽는 것이 아닌 파생 근사다.
- 약한 확산 반사(bounce) PNG는 계속 생성하지만 실행 시 불러오지 않는다(검증 안 된 태양 반사 미사용).
- 본 건물(층수·외장·주차 시안)은 베이크에 들어가지 않으므로 시안 변경과 무관하다. 그림자는 실시간 태양이 그린다.

아래는 2026-10-16 최초 기록이다.

## 실제 적용 범위

도로·인도 등 높이 -0.6~0.7m 범위의 고정 지면 36개 면에 월드 좌표 UV1을 생성해 AO 맵과 약한 확산 반사 라이트맵을 연결했다. 원본 건물 기하/UV/생성 코드는 건드리지 않았다. 주변 환경 메시도 원본을 수정하지 않고 수신 지면만 복제해 UV를 추가한다.

`bake-ground.mjs`는 Three MeshBVH로 172,566개의 주변 기하 삼각형에 대해 512×512 격자, 픽셀당 코사인 분포 32방향, 최대 24m 거리의 차폐를 계산한다. 하늘 차폐율과 차폐 표면 색상의 약한 확산 반사 근사를 각각 PNG로 저장한다. 계산 약 9.3초는 개발 환경에서 한 번만 실행하며, 접속한 브라우저는 약 120KB의 결과만 불러온다. 영역은 x/z ±112m, 수신 높이 0.38m이고 맵 외곽은 중립값이다.

**이는 전체 GI 베이킹이 아니다.** 본 건물, 알파 나뭇잎과 고밀도 스캔 메시를 제외한 단순 불투명 주변 기하를 사용한다. 파사드 전체의 간접광이나 다중 반사, 정확한 태양광 에너지를 계산하지 않았다. 기존 실시간 그림자와 접촉 음영을 보존한다. 베이킹의 품질 보강 효과와 속도 향상을 혼동하지 않는다.

주변 도시/인접 건물을 끄면 베이킹도 꺼서 없는 건물의 음영이 남지 않도록 한다. 주변 건물 배치가 바뀌면 아래 입력 스냅샷을 다시 추출하고 베이크해야 한다. 층수·외장·주차 시안 변경은 본 건물을 베이크에서 제외했으므로 그대로 지원한다.

## 유리

기존 금속성 0.32의 푸른 유리 근사를 기본 금속성 0의 유전체로 조정했다. 밝은 중성 색상, IOR 1.52, 약한 거칠기와 코팅 반사를 사용한다. 표면 법선과 시선 사이 각도의 5제곱 함수를 통해 정면의 투명도와 비스듬한 면의 반사를 다르게 표현한다. 실제 주변 장면 큐브 반사는 계속 사용한다. 이 실시간 표현도 정확한 다중 유리 굴절의 대체품은 아니다. 별도 정밀 렌더는 원래 물리 재질을 유지한다.

보기 방식 아래 **환경 베이킹·유리 개선** 체크를 끄면 동일 시안/카메라에서 이전 표현을 볼 수 있다. 두 변경을 함께 비교하며, 베이킹만의 단독 성능 개선이라고 해석하지 않는다.

## 비교와 검증

- [전후 실제 화면](bake-comparison.html), [측정 원본](bake-benchmark.json).
- 같은 Mac/Chrome, 로컬 서버/브라우저 캐시. 이전 초기 준비 15.14초, 이번 16.13초. 엄격한 cold-cache 반복 벤치마크가 아니다. 추가 베이크 로드/지면 UV·재질 적용은 약 0.288초다.
- 같은 40단계 카메라 경로를 전→후→전→후 순서로 실행. 매 단계 두 animation frame 및 GPU 큐 완료를 기다리고 첫 4회는 제외했다. 이전 중앙값 118.1/123.9ms, 이후 123.9/119.8ms. 평균 중앙값 121.0→121.85ms로 실질적 속도 개선이라고 보기 어렵다. 이 측정은 FPS와 다르다.
- 자주식3+석재 변경 후 부모·자식 state 일치, 베이킹 유지, 주변 도시 숨김 시 베이크 해제를 확인했다.
- 기본은 interactive 모드이며 광선 추적 누적 대기가 없다. 원본 설계 모델 복사/창호/배칭 회귀 테스트와 JS 구문 검사, 번들 빌드 통과.

## 재생성

브라우저에서 `TOWER_CINEMA.groundSource()` 결과를 JSON으로 저장해 `tools/360/bake-static-source.json.gz`로 압축한 뒤, `tools/360`에서 `node bake-ground.mjs bake-static-source.json.gz` 실행(약 6초). 입력에 서명이 없으면 스크립트가 중단한다. `new/360/assets/ground-bake.json`에 입력 SHA256과 베이크 설정을 기록했다. 입력·스크립트·PNG 결과를 모두 분리 브랜치에 보존한다.

기술적으로 적용·실행된 상태지만, 주변 건물 표면 자체의 완전한 조명 베이킹과 실사 수준의 사실감은 남은 과제다.
