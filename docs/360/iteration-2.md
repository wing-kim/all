# 360° 시각화 — 실사 품질 개선 2차 기록

2026-10-15. 초기 검증 보고서는 [assessment.md](assessment.md)에 보존한다. 이번 기록은 완성된 실사 재현을 선언하는 문서가 아니다. 현재 실사 원본과의 차이, 특히 주변 건물의 세부 형상과 도시 밀도는 계속 개선할 대상이다.

## 현재 구현

- 기존 Three.js r128 모델 생성 코드를 구조 기준으로 유지한다. 새 렌더러는 같은 정점·변환을 복사해 사용한다. AI 이미지에 맞추려고 코어 벽이나 층고를 바꾸지 않는다.
- 지원 브라우저에서는 Three.js 0.186.1 + three-gpu-pathtracer 0.0.27의 WebGPU 광선 추적을 사용한다. Open Image Denoise를 브라우저 안에서 실행한다. 서버 GPU, 유료 서비스, 모델 업로드는 사용하지 않는다.
- 이동 중과 정밀 계산 중에는 같은 장면의 실시간 렌더를 표시한다. 노이즈 제거가 끝난 정지 화면만 정밀 결과로 표시해, 몬테카를로 노이즈가 지면 깜빡임처럼 보이는 일을 줄인다.
- WebGPU가 없으면 기존 WebGL 실시간 경로를 사용한다. 두 경로 모두 실제 연속 3D이며, 원본 비교 이미지의 각도 전환은 오른쪽 비교 패널에만 적용한다.
- 유리 투과, 주변 장면 반사, 실내 면광원, 표면 법선·거칠기, 하늘 배경, 외벽·창 프레임·블라인드·실외기·상가 창호·옥상 설비, 포장·연석·배수구를 추가 또는 개선했다.
- 도면 방위 화살표를 새 뷰어에서 숨겼다. 기존 도면 뷰는 보존했다. 도로/보도/대지의 높이를 분리하고 중복 구형 차선 메시를 제거했다.
- Poly Haven 수목과 PBR 재질, Car Concept 차량을 재사용했다. 수목은 잎 단위 샘플링, 실루엣 조정, 메시 단순화와 Draco 압축을 거쳤다. 출처·라이선스는 [assets/README.md](../../new/360/assets/README.md)에 있다.
- 주변 아파트는 기존 코드의 현황 그룹을 사용한다. 장래 재건축 가정을 기본 장면에서 제외했다. 새 원경은 예시 도시 모델이며 현장 측량 자료로 주장하지 않는다.
- 앞/뒤/좌/우/코너/조감도, 드래그 회전, 휠 확대, 자동 회전, 주변 건물 표시, 비교 패널, GLB 저장을 제공한다.

## 확인한 검증

독립적인 원형 모델(`?lab=verify`, alt4)과 개선 모델을 비교했다. 원래 부재 3,234개, 위치 정점 119,173개 및 로컬 변환을 대상으로 1e-4 단위의 FNV 형태 해시를 계산했으며 두 모델 모두 **3710930476**이었다. 정적 배칭으로 추가한 렌더 메시를 제외하고 원형 부재를 비교했다. 이 검사는 설계 인증이 아니라 코드에서 형상을 보존했는지 확인하는 검사다.

[여섯 방향 검사](evidence/cinema-view-tests.json)는 모든 시점에서 같은 형태 해시, 카메라 반경 62m, 원형 카메라와 정밀 카메라의 위치 일치를 확인했다. [실제 마우스 드래그 검사](evidence/cinema-drag.json)는 32개 입력 구간에서 약 399.6°의 연속 회전을 기록했다.

`npm ci --ignore-scripts`와 `npm run build`를 고정 버전 잠금 파일로 검증했다. 최초 잠금 파일의 플랫폼 경로 문제를 수정한 뒤 재실행하여 통과했다. JavaScript 구문 검사와 `git diff --check`도 통과했다. 면광원 보조 렌더의 LTC 초기화 오류는 라이브러리 초기화를 추가해 해결했다.

[입력·내보내기 검사](evidence/cinema-interaction.json)에서 마우스 휠로 카메라 반경이 62m에서 58.9m로 감소했고, 주변 건물 숨김 시 정밀 장면의 해당 메시가 모두 숨겨지는 것을 확인했다. 형상 GLB는 6,275,104바이트이며 glTF 2.0 매직·버전·파일 길이가 일치했다.

수목 밀도 시험 중 기본 WebGPU 저장 버퍼 한도 문제가 발생했다. 어댑터가 지원하는 범위 안에서 최대 512MiB의 버퍼 한도를 요청하도록 변경했다. 이는 해당 메모리를 선할당한다는 의미가 아니다. 잎을 68% 보존하고 메시를 20%로 단순화하여 수관 밀도와 기하 복잡도를 분리했다. 최종 장면은 다시 48샘플 수렴과 노이즈 제거를 완료했다. 비동기 GPU 검증 오류가 발생하면 실시간 렌더로 돌아가도록 처리했다. 이동 화면의 유리에는 같은 장면에서 촬영한 반사 큐브맵을 사용한다.

화면 크기 변경 검사에서 노이즈 제거용 보조 렌더의 굴절 버퍼가 이전 크기를 참조하는 오류를 발견했다. 알베도·법선 가이드 버퍼를 계산할 때 불필요한 굴절 패스를 끄도록 수정했다. 1440px 검사 화면에서 실제 창 크기로 돌아간 뒤에도 48샘플 수렴·노이즈 제거가 다시 완료됐고, 새 GPU 오류가 없었다.

원경에는 ambientCG Facade 018 A(CC0)의 벽돌·유리 PBR 재질을 추가했다. 가로수 식재 경계, 모서리를 깎은 연석, 주변 건물 옥상 표면도 보완했다. 주광과 환경광 비율은 화면 비교 후 조정했으며, 넓은 화면에서는 OIDN 정식 크기 가중치(1.84MB), 좁은 화면에서는 소형 가중치를 사용한다. 정식 크기 가중치로도 48샘플 수렴과 노이즈 제거 완료를 확인했다.

이동 중 실시간 표시에는 깊이 기반 GTAO, 공간 노이즈 제거와 FXAA를 적용했다. 굴절 유리의 이동 화면과 정지 화면 사이 밝기 차이를 줄이기 위해 실시간 드로우에서만 유리 색을 보정하며, 원형 재질과 광선 추적 재질은 유지한다. 주변 현황 아파트에도 창 프레임과 옥상 재질을 추가하되 상가 디테일은 적용하지 않는다. [후면 비교](evidence/cinema-back.png)에서 48샘플 및 노이즈 제거 완료를 확인했다. 원본 AI 이미지의 고층 재건축 배경과 달리 현황 아파트를 표시한다.

## 시각적 판단과 남은 작업

[정밀 코너 비교](evidence/cinema-corner.png)는 초기 화면보다 하늘, 유리, 간접광, 접촉 그림자, 포장, 차량과 수목이 개선됐음을 보여준다. 원본 실사와 동등한 수준이라고 판정하지 않는다. 근거리 도시의 창호·상가 디테일, 원경의 다양성, 지면의 자연스러운 사용 흔적이 여전히 부족하다. AI 원본의 잘못된 면이나 부재 위치를 복제해 차이를 줄이지 않는다.

정밀 렌더는 장치와 화면 크기에 따라 수렴 시간이 달라진다. 표시되는 샘플 수와 노이즈 제거 완료 상태를 확인할 수 있다. 정지 후 계산 시간이 있다는 점은 실시간 조작 가능 여부와 별도로 평가한다. 이동 중에는 같은 장면의 실시간 표시를 유지한다. 390px 반응형 배치와 WebGL 호환 모드를 검사했다. 좁은 화면은 비교 이미지를 접고 균형 품질로 시작한다. 이 검사는 데스크톱 브라우저 에뮬레이션이며 모바일 실기기 성능 검증은 아니다. 장시간 GPU 메모리 사용량과 배포 후 캐시/네트워크 동작도 추가 검증 대상이다.

## 실행과 재현

로컬 서버 실행 시 [기본 뷰어](http://127.0.0.1:8765/new/360/), [정밀 보기](http://127.0.0.1:8765/new/360/?engine=cinema), [WebGL 실시간 보기](http://127.0.0.1:8765/new/360/?engine=realtime)를 사용할 수 있다. localhost 링크는 이 컴퓨터에서만 동작한다. GitHub Pages 공개 경로 반영 여부는 PR/배포 상태와 별도로 확인해야 한다.

렌더러 빌드: `tools/360/`에서 `npm ci --ignore-scripts`, `npm run build`. 정적 번들은 `new/360/modern.js`이며 Pages에서 실행에 Node 서버가 필요하지 않다. 수목 가공 스크립트는 `tools/360/prepare_tree.py`이며 Blender에 `-- 원본.gltf 출력.glb` 인자를 전달한다.

기술 근거: [three-gpu-pathtracer](https://github.com/gkjohnson/three-gpu-pathtracer), [Poly Haven 라이선스](https://docs.polyhaven.com/en/faq), [Car Concept](https://github.com/KhronosGroup/glTF-Sample-Assets/tree/main/Models/CarConcept), [OIDN 가중치](https://github.com/RenderKit/oidn-weights). 이미지 기반 재구성을 선택하지 않은 이유는 초기 보고서의 다중 시점 일관성 검토를 따른다.

GitHub 변경은 `codex/tower-360-validation` 전용 브랜치와 초안 PR #1에서 관리한다. `main` 직접 수정이나 병합은 수행하지 않았다.

추가 표면 개선: 주변 건물의 위치에서 결정되는 고정 색상 변주를 적용해 모든 외벽이 같은 흰색으로 보이는 문제를 줄였다. 도로 보수 포장 3곳과 맨홀 4곳을 별도 높이로 추가했다. 보수 포장 상단은 0.012m, 맨홀 상단은 0.022m로 기존 차선(0.045m)보다 낮다. 실제 위치를 측량한 시설물은 아니며 주변 환경의 예시 디테일이다. 754px 실제 창 크기에서 32샘플 수렴과 노이즈 제거 완료 화면을 확인했다. 본 건물 생성 코드는 이 변경에서 수정하지 않았다.
