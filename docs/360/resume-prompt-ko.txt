주간 사용량이 실제로 초기화된 뒤의 작업이다. 새 대화 생성만으로 한도가 초기화됐다고 가정하지 마. 이번 작업은 계정의 주간 전체 사용량 50%를 절대 넘기지 않는 범위에서 끝내줘. 추가 50%포인트를 쓰라는 뜻은 아니야. 45%부터 최종 검증·저장·인계에 집중하고, 48%까지 산출물을 마무리하여 50% 전까지 여유를 남겨줘. 다른 작업과 서브 에이전트의 사용량도 포함해서 확인하고, 유료 서비스나 리셋 크레딧은 승인 없이 사용하지 마.

Astra가 설계·품질 검수·최종 판단을 맡고, GPT-6.1 Sol 서브 에이전트가 구체적인 구현·테스트를 맡아줘. 이 역할 분담과 Sol 사용을 승인한다. 기본은 Sol 1개를 순차 실행하고, 전체 대화 대신 필요한 파일·제약·완료 기준만 전달해서 사용량을 아껴줘.

목표는 기존 2D 실사에서 느끼던 현실감을 3D로 실제 체험하고 도입 여부를 판단하는 것이야. 기존 후보안의 확정 구조와 시안 선택은 유지해줘. AI 이미지의 모순된 형태를 모델에 옮기지 마.

핵심 체험을 완결해줘: 외관 시안 선택과 자유 회전 → 1층 카페 눈높이 탐색 → 같은 구조의 최소 2가지 실내 시안 3D 비교 → 원본 실사와 나란히 비교 → 외부 복귀. 카페 자연광·간접광·유리·바닥·가구의 사실감, 회전 직후 품질, 초기 로딩과 입력 안정성을 우선해줘. 정밀 렌더는 별도 버튼으로 유지하고, 다른 층 전체 제작은 필수 범위가 아니야.

실제 Chrome 화면과 측정으로 검증하고 중간 결과를 간결하게 보고해줘. 모든 층을 만들거나 새 기능을 계속 추가하며 끝없이 개선하지 마. 예산이 부족하면 선택 확장을 제외하고 핵심 체험과 인계를 우선해줘. 실사 품질에 미달하면 원인과 한계를 솔직히 명시해야 해.

최종적으로 내가 실제 사용 여부를 결정하고 다른 사람이 후속 작업을 이어갈 예정이야. 따라서 작업의 마지막 단계는 후속 담당자에게 그대로 전달할 독립적인 프롬프트를 작성하는 것이야. 최종 코드·비교 이미지·검증 결과·실행법·미해결 우선순위를 저장하고, docs/360/final-handoff-prompt-ko.txt에 최종 커밋과 이어받는 방법을 포함해 작성한 뒤 응답에도 전달해줘. main은 교체하지 말고 기존 분리 브랜치에 커밋·푸시해줘.
