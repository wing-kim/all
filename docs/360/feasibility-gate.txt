목표 달성 가능성 재검토 — 2026-10-16
기준: 80f73a7, 실제 구현 8a6f095. git fetch 후 origin/main 추가 미병합 커밋 없음. 작업 트리 깨끗함. 주간 사용량97%, 아직 초기화 전. 이번 평가는 소스·기존 Chrome 캡처 cafe-opaque-fix.jpg·검증 기록 및 Sol 독립 코드 검토에 근거하며 새 브라우저 성능 측정을 했다는 뜻이 아니다.

판단
1. 원본 구조/시안 유지, 화면 통합, 연속 회전, 두 실내 시안, 정적 별도 배포는 현재 웹 기술로 구현 가능한 범위. 계정 Pages 자격은 여전히 확인 필요.
2. 전체 외관·실내·주변 모든 각도에서 원본 AI 실사와 동등한 품질, 회전 직후 즉시 출력, 임의 구조/시간대 변경, 제한 예산을 모두 만족한다고 현재 계획만으로 보장할 수 없다. 현재 시각 증거는 기준 미달이다. 단순 수치 조정/무료 가구 교체만으로 목표 달성을 전제하지 말 것.
3. 원본 AI 이미지끼리 구조가 모순되면 정확한 한 3D 구조로 모든 이미지를 동시에 재현할 수 없다. 형태는 설계 기준으로 고정하고 빛/재질/분위기를 비교한다.
4. Three.js 자체가 결정적인 장애라는 근거는 없다. 실제 간접광 베이크·정확한 재질·반사·고품질 자산 제작 경로가 빠져 있는 것이 우선 병목이다. 엔진 전면 교체만으로 해결되지 않는다.

코드 근거
- cafe.js: 카페 바닥 aoMap. 문서상 512²/64방향/2.5m 접촉 AO이며 실내 전체 간접광 라이트맵 아님.
- modern-entry.js: 재질 복사에 lightMap 전달 없음. RectAreaLight로 창가/바닥 bounce 근사.
- preview 유리는 transmission=0 + alpha/Fresnel + 단일 외부 probe(-3,18,0). 카페 위치에 맞는 시차 보정 실내 반사가 아님.
- 정밀 렌더는 별도 경로. 정밀 스틸 향상을 기본 탐색 품질의 성공 증거로 쓰지 말 것.
- 구조/가구 변경 시 기존 베이크 재사용은 오류 가능. 구조/시안/시간대 키와 무효화·재베이크 정책 필요.
참고: https://threejs.org/docs/pages/MeshStandardMaterial.html (lightMap은 베이크 조도 데이터와 별도 UV 필요)
https://threejs.org/docs/pages/MeshPhysicalMaterial.html (고급 물리 재질의 픽셀 비용)

보완된 실행 순서
원래 UI 통합 우선 요구는 유지하되 최소 연결/상태 계약만 먼저 정의하고, 대규모 통합·두 시안·배포 완성을 시작하기 전에 대표 품질 게이트를 둔다. 이는 사용자 최신 ‘가능성 먼저 판단’ 요청 반영이다.
- 한 구조, 한 주간 조명, 카페 창가~카운터 구역으로 고정.
- 바닥·벽·천장에 실제 조도/간접광 라이트맵을 베이크하고 source→modern 재질/UV 경로 검증. AO와 GI를 구분. 중복 조명 방지.
- 배포 허용 무료 고품질 의자/테이블 등 소수 자산을 실척 적용. 창/바닥 반사는 작은 범위의 planar 또는 시차 보정 probe를 시험하고 비용 측정.
- 원본 동일 구도에 근접한 창가/카운터/반대 방향 3시점, 이동 직후 첫 프레임, 연속 회전 화면 비교. 정밀 렌더 OFF. 구조 고정·이중상 없음·가구 부유/관통 없음 확인.
- 동일 기기/뷰포트에서 로딩과 프레임 시간 측정. 30fps(33ms) 이상은 잠정 목표이지 측정 완료 수치 아님. 대기 없는 기본 화면과 실제 품질을 함께 검수.
- 초기화 후 전체 사용량10%까지 게이트 1차 판단, 최대15%까지 한 차례 수정. 이는 다음 주간50% 안에 포함된다. 개선이 불충분하면 확장을 멈추고 기술 변경/범위 조정과 근거를 사용자에게 보고한다. 품질 기준을 몰래 낮추지 말 것.
- 통과 시 UI 전체 통합→실내2시안→독립 배포→회귀검증→후속 담당자 인계. 45/48/50% 마감 조건 유지.

현재 결론: 기능 완성은 타당하나 원본 실사 수준 달성은 미검증. 현재 방식 그대로 목표 달성 가능으로 승인하지 않음. 대표 품질 증거 확보 전 전체 제작 재개를 조건부로 둔다. 사용자가 가능성 판단을 요청했으므로 이 한계를 먼저 전달하고 무조건 성공을 약속하지 않는다.

외부 검증 추가 — 사용자 지시 2026-10-16
실내만 통과해 전체 목표 달성 가능으로 판단하지 않는다. 실내와 외부를 독립적인 필수 게이트로 평가하고 둘 다 통과해야 확장한다. 총 검증 예산은 합산10% 1차/15% 보완 상한이며 각각15%가 아니다.

외부 대표 범위
건물 일부만 잘라 보는 것이 아니라 목표 건물 전체를 유지하고, 도로와 인도가 만나는 대표 코너의 근거리 환경을 집중 개선한다. 나머지 방향도 기존 전체 환경을 유지하여 빈 배경/품질 급락을 확인한다.
- 원본 실사 조감 구도, 거리 눈높이 코너, 후면/반대편의 최소3시점과 건물 전체 360도 연속 회전.
- 건물 비율·입면·창호·유리 너머 실내·외장 재질을 먼저 평가. 특정 각도에만 맞춘 이미지 투영이나 면별 구조 변경 금지.
- 밝고 선명한 주간 하늘, 태양 방향/그림자와 HDR 반사의 일치, 노출·색감 확인.
- 차도/보도 경계·연석·포장 질감·차선·접지 그림자·인접 건물의 입면 깊이/창호를 검토. 실제 대지/도로 배치는 자료 우선, 불명확한 주변 상세는 추정 표시.
- 차량은 차로/진행 방향·주차 공간에 맞추고 인도 침범·겹침·부유를 제거. 나무는 적절한 크기/배치와 잎 alpha 깜빡임을 점검. 도로 화살표 등 원본 AI 오류를 자동 복제하지 않는다.
- 무료 고품질 차량/나무 자산은 공개 웹 배포 허용 라이선스와 성능 확인 후 활용. 가까운 주변은 충분히 상세하게, 먼 건물은 거리별 상세도 조절을 허용하되 사진 같은 거리감을 유지.

외부 기술 판단
현재 HDR 하늘, 실시간 태양광, 외부 반사 probe, 지면 AO/확산 bounce 베이크는 구현돼 있다. 지면 베이크는 baked-ground.js가 modern 재질에 직접 적용하므로 source 재질 복사의 lightMap 누락과 구분할 것. 그러나 이것이 주변 도시/본 건물 전체의 GI 또는 사실적인 위치별 유리 반사를 입증하지 않는다. 단일 probe로 가까운 주변/실내 반사 위치가 어긋날 수 있고, 정적 주변 베이크와 가변 건물의 동적 그림자는 조합·무효화 검증이 필요하다.
기술적으로 개선할 경로는 있으나 원본 실사 수준 달성은 외부도 미검증이다. 엔진 유지/변경 결론은 이 비교 결과로 내린다.

판정 기록
실내와 외부 각각 구조 정확도, 재질/유리, 조명/색감, 환경 배치, 이동 중 일관성, 성능을 통과/미달/미확인으로 기록한다. 정밀 렌더 OFF, 동일 기기/뷰포트로 회전 직후 캡처·연속 회전·cold/warm 로딩을 비교한다. 외관 시안 최소2개로 구조 및 그림자 회귀도 확인한다. 한쪽만 좋아져도 전체 성공으로 합산하지 않는다. 실패 시 그 원인과 변경 비용/범위를 먼저 보고한다.

[불확실할 때의 사례 조사 — 사용자 추가 지시]
실내 또는 외부 품질 개선이 정체되거나 현재 접근법의 달성 가능성이 불확실하면 자체 실험을 반복하기 전에 실제 유사 성공 사례를 조사한다. 건축/인테리어를 사진처럼 보여주는 연속 자유 시점 웹 데모와 공개 제작 설명을 우선하며, 정지 렌더·파노라마·이미지 전환을 자유 3D 성공 사례로 혼동하지 않는다. 직접 실행 가능한 사례의 이동 직후 품질, 유리/간접광, 외부 환경, 로딩, 대상 기기, 모델·텍스처 크기, 베이킹/반사 방식, 호스팅/서버 의존성과 비용을 비교한다. 제작 방식이 공개되지 않은 부분은 추정으로 표시하고 성공했다고 광고하는 문구만으로 판단하지 않는다. 가장 유사한 소수 사례에서 재현 가능한 방법을 선정해 대표 실내/외부 구역에 검증한다. 이 조사도 전체 사용량 및 품질 게이트 예산에 포함하고, 결과/출처/채택·배제 이유를 기록한다.
