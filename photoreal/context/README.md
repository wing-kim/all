# 주변 건물 데이터 (photoreal/context)

케이프혼타워 대지(서울 강남구 신사동 529 외 2필지, 압구정로 112 동광빌딩 자리) 주변 건물을 실측 자료로 다시 만든 데이터와 three.js 모듈입니다. 실사 3D 계층(`photoreal/kh-photoreal.js`)이 불러 쓰는 것을 전제로 하며, 이 폴더는 장면에 직접 아무것도 넣지 않습니다. 용도는 내부 검토용 테스트입니다.

## 파일

| 파일 | 내용 |
|---|---|
| `buildings.json` | 근경(대지 중심 250m 이내)과 원경(250m～1.2km) 건물 목록과 좌표 변환 정보 |
| `kh-context.js` | `buildings.json`을 읽어 재질 분류별로 병합한 `THREE.Group`을 돌려주는 모듈(r128 전역 `THREE` 사용) |
| `near_roadview.json` | 로드뷰로 확인한 근경 건물 기록(사람이 작성하는 입력 파일) |
| `build_context.py` | `buildings.json` 생성 스크립트 |
| `fetch_vworld.py` | 브이월드 건물 자료(LT_C_BLDGINFO)와 대지 주변 연속지적도(LP_PA_CBND_BUBUN) 받기(인증키 필요, 원본은 `.cache/`에만 저장) |
| `ref/` | 로드뷰 확인 캡처(카카오 로드뷰 2026년 6～7월 촬영분, 640px 저용량 JPG) |
| `.cache/` | 원본 자료 보관 위치(커밋하지 않음) |

## buildings.json 구조

```
{
  meta: { transform, counts, classes, license, osm_timestamp, vworld_count },
  wing_diff: [ Wing 근사값과 실측 비교 ],
  buildings: [ {
    id, name, src(osm|vworld), near(bool), dist(m),
    outline: [[x, z], ...],   // Wing 월드 좌표(m)
    h(m), floors, floor_h(m), cls, color("#rrggbb"), color2("#rrggbb"), win_ratio(0～1),
    verify(roadview|api|osm|estimate), verify_all, estimated(bool), floors_api, approved,
    shop_glass, windows, rooftop, confidence, ref, note   // 로드뷰 확인 건물만
  } ]
}
```

좌표는 Wing의 `new/3d-model.html`과 같습니다. 도면 픽셀 `(px, py)`에 대해 `x = (px-914)/41.6`, `z = (py-770)/41.6`이고 y가 위쪽입니다. 건물은 바닥 y=0에서 `h`까지 세웁니다.

재질 분류(`cls`)는 `tile`(흰 타일·벽돌 타일), `stone`(석재·석재 패널, 띠창), `glass`(유리 커튼월), `brick`(적벽돌·짙은 벽돌), `paint`(도장·회백색 마감), `metal`(금속 패널), `apt`(아파트 도장 외벽과 발코니 창) 7가지입니다. `color`는 외벽 대표색, `color2`는 띠·창틀·포인트 색(둘 다 sRGB)이고 `win_ratio`는 벽면 중 창이 차지하는 대략의 비율입니다. 로드뷰로 본 건물은 사람이 기록한 값이고, 나머지는 재질 분류별 가정값입니다(유리 0.8, 아파트 0.45, 석재 0.35, 금속 0.3, 타일·벽돌 0.25, 도장 0.22). `rooftop`은 옥탑·후퇴층·경사 지붕 메모, `confidence`는 로드뷰 위치와 건물 대응의 신뢰도입니다(중간 = 지도로 추정한 대응이라 이웃 건물과 바뀌었을 수 있음).

## 좌표 변환

- 위경도를 원점 37.5230N 127.0213E 기준의 로컬 동·북 거리(m)로 바꾼 뒤(`east = (lon-lon0)·88288.88`, `north = (lat-lat0)·110574`), 2x2 행렬과 이동량으로 Wing 월드 `[x, z]`로 옮깁니다. 값은 `meta.transform`에 있고 `KHContext.lonLatToWorld(meta, lat, lon)`로 계산할 수 있습니다.
- 변환은 축척 1의 강체 변환(회전, 이동, 도면의 남북 뒤집힘)입니다. Wing의 우리 건물은 설계 도면(대지 749㎡)에서 그려 실제 치수이므로 축척을 고정했습니다.
- 대응점은 브이월드 연속지적도의 대지 필지 3개(신사동 529, 529-1, 529-8, 합계 746㎡)를 합친 외곽 네 꼭짓점과 Wing `SITE` 네 꼭짓점입니다. 오차는 최대 0.08m, RMS 0.05m입니다.
- 같은 변환에서 OSM의 동광빌딩·3번지 건물 외곽선과 Wing `existBuilding()` 외곽선의 꼭짓점 차이는 RMS 2.6m(최대 4.2m)입니다. 이는 OSM 외곽선과 Wing 도면 건물의 차이이며 좌표 변환 오차가 아닙니다. 필지 자료가 없으면 이 건물 꼭짓점 8개로 맞추는 방식으로 되돌아갑니다(오차 RMS 1.5m).
- 변환으로 구한 실제 북쪽은 도면 좌표에서 수평선 위 약 32.6°입니다. Wing의 `NORTH_DEG=36`과 약 3.4° 차이가 납니다(해·그림자 방향에 영향, Wing 값은 고치지 않았습니다).

## 높이·층수 정하는 순서

1. 브이월드 LT_C_BLDGINFO의 `grnd_flr`(지상층수)와 `height`. 높이가 0이거나 층수와 맞지 않으면(층당 2.4m 미만, 7.5m 초과) 층수 × 층고 + 파라펫으로 계산합니다
2. 로드뷰로 센 층수(`near_roadview.json`)가 있으면 그것을 우선합니다. 자료 층수와 다르면 높이도 로드뷰 층수로 다시 계산하고 자료 층수는 `floors_api`에 남깁니다
3. OSM `height`, `building:levels`
4. 추정: 용도와 바닥면적으로 층수를 정하고(근생 120㎡ 미만 2층, 300㎡ 미만 4층, 800㎡ 미만 5층, 2000㎡ 미만 7층, 그 이상 10층, 아파트 12층, 학교 4층) 층고(근생 3.5m, 업무 3.6m, 아파트 2.9m, 학교 3.8m)를 곱합니다. `estimated: true`, `verify: "estimate"`로 표시합니다.

로드뷰 기록이 없는 건물의 재질·색은 추정값입니다. 용도(아파트·학교·주택), 높이(30m 이상은 유리·석재), 사용승인 연도(1995년 이전은 타일·벽돌·도장 위주, 2010년 이후는 유리·석재·금속 위주) 비율에 따라 건물 id 해시로 고릅니다.

브이월드 기록 중 같은 자리에 겹친 것(한 건물의 중심이 다른 외곽선 안)은 넓은 외곽선 하나로 합치고 층수·높이는 큰 값을 씁니다. 대지 안(Wing `SITE`)의 건물은 Wing 장면에 이미 있으므로 뺍니다.

## kh-context.js 사용

```js
// <script src="../photoreal/context/kh-context.js"></script> 뒤에
const grp = await KHContext.load('../photoreal/context/buildings.json', { near: true, far: true });
scene.add(grp);
console.log(grp.userData.stats);   // { buildings, triangles, drawCalls, meshes }
```

- 메시: 근경은 분류별 7개 + 1층 상점 유리 띠(`ctx_shop`), 원경은 `ctx_far_light`·`ctx_far_dark`·`ctx_far_glass` 3개, 지붕은 전체 `ctx_roof` 1개입니다. 현재 자료로 3,888동, 삼각형 69,478개, 그리기 호출 12회입니다(예산 30만 개, 10회 안팎). 근경만 켜면 258동입니다.
- `ref/render_*.jpg`는 이 모듈의 기본 재질로 그린 확인용 화면입니다(`render_16번과_같은_시점`은 로드뷰 16번과 같은 위치·방향).
- 건물 색은 꼭짓점 색(`color` 속성, 선형값)에 들어 있고 재질 색은 흰색입니다. XR 병합이 원본 재질을 그대로 묶는 방식에 맞췄습니다.
- UV는 u = 벽을 따라간 거리 / 3.2m, v = 높이 / 그 건물의 층고입니다. 창 텍스처 한 칸이 기둥 한 칸·한 층이 되므로 실사 재질을 넘길 때도 이 규칙에 맞춘 반복 텍스처를 쓰면 됩니다.
- 옵션: `material(cls)`로 재질을 직접 넘길 수 있습니다(없으면 64px 절차적 창 텍스처 재질). `exclude: [id]`, `filter(b)`, `maxDist`, `near`, `far`, `shadows`.
- Wing의 `buildContext()`가 만든 근사 주변 건물과 겹치므로, 연동할 때 Wing의 주변 건물 그룹은 숨겨야 합니다(연동은 실사 3D 세션 몫).

## 다시 만드는 절차

```bash
cd photoreal/context
python3 build_context.py                      # .cache/osm.json 이 없으면 Overpass에서 받음
VWORLD_KEY=발급키 python3 fetch_vworld.py   # 브이월드 건물(층수·높이)과 대지 필지 경계
python3 build_context.py                      # .cache/vworld.json 이 있으면 외곽선·층수·높이를 우선 사용
```

필요한 것은 Python 3와 numpy입니다. 인증키는 Jack의 브이월드 계정 마이포털 > 인증키관리에 있는 개발키(서비스명 "Jack 건물 형태 검토", 2D데이터·WMS/WFS API, 만료 2027-04-30)를 쓰며 저장소에는 넣지 않습니다. 로드뷰로 확인한 건물을 늘리려면 `near_roadview.json`에 OSM way id(또는 `ll:위도,경도`)를 키로 항목을 더하고 다시 생성합니다.

## 남은 미확인 사항

- 로드뷰로 확인한 건물은 근경 40동입니다(대응 신뢰도 높음 25, 중간 15). 나머지 근경 218동의 재질·색은 추정입니다. 현대고와 가로수길 남쪽은 아직 보지 않았습니다.
- 건축물정보 층수가 실제와 다른 경우가 있습니다(116, 118처럼 증축분이 대장에 없는 경우). 로드뷰로 보지 않은 건물은 자료 값을 그대로 씁니다.
- 높이 0인 기록은 층수 × 가정 층고라서 실제 높이와 1～3m 차이가 날 수 있습니다.
- 옥탑·후퇴층·경사 지붕은 형상으로 표현하지 않았습니다(평지붕 압출). 로드뷰로 본 건물은 `rooftop`에 적었습니다.
- 에스모드서울 외벽은 가로수에 가려 재질을 확실히 보지 못했습니다(회색 석재로 둠).
