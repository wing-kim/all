## 3. 직접 확인하실 순서 (약 10분)

크롬이나 엣지 최신 버전을 권장합니다. 실사 3D는 WebGPU라는 비교적 최근의 그래픽 기능으로 그리기 때문에, 이를 지원하지 않는 브라우저에서는 '실사 3D' 선택지가 회색으로 비활성화되고 그 아래에 어떤 브라우저가 필요한지 안내가 나옵니다. 선택지가 막혀 있어도 원본 보기(스케치업 등)는 평소대로 쓰실 수 있습니다. 고른 뒤에 렌더러가 실패하는 경우에도 몇 초 안에 원본 화면으로 되돌아가고 같은 안내를 알림으로 보여 줍니다. 화면이 멈춘 채로 남는 일은 없습니다.

## 5. 기술 설명 (정확한 용어)

이 절은 나중에 개발자나 AI 도구에 설명하실 때 그대로 쓰셔도 되는 내용입니다.

### 5.1 전체 구조

1. **원본 앱**: `new/3d-model.html`. three.js r128(WebGL) 기반이며 건물 형상(`LEVELS`, 시안별 외장), 시안 선택 UI, 카메라 조작(OrbitControls 유사)을 담당합니다.
2. **실사 렌더러**: 같은 페이지 안의 iframe(`?lab=360&engine=cinema`)에서 three.js **0.186 WebGPU 렌더러**(`WebGPURenderer`, 노드 재질 `MeshPhysicalNodeMaterial`, 셰이더 언어 TSL)로 그립니다. 소스는 `tools/360/*.js`이고 esbuild로 묶어 `new/360/modern.js`가 됩니다.
3. **연결부**: `new/360/integrated.js`가 원본 화면과 실사 iframe을 잇습니다. 원본이 입력과 카메라를 소유하고(`drive()`로 카메라 위치·목표·화각 전달), 실사 쪽은 원본 장면을 **복사(scene copy)** 해서 같은 형상을 실사 재질로 다시 그립니다. 시안을 바꾸면 원본이 건물을 다시 만들고, 실사 쪽도 같은 설정으로 다시 복사합니다(`applyConfig` → `updateBuilding`).
4. **실사 쪽 장면 꾸밈**: `new/360/scene.js`(iframe 진입점), `environment.js`(가로수·차량·포장·주변 건물 디테일), `cafe.js`(1F 카페), `office.js`(2F～6F 실내와 지하 주차장 마감), `interior-models.js`(가구 모델 지연 로드).

### 5.2 화질

1. **물리 기반 재질(PBR)** 과 **HDR 환경광**(Poly Haven 하늘, CC0), 태양 방향의 **그림자 맵(shadow map)**.
2. **유리**: 움직이는 미리보기에서는 투명도와 프레넬 반사를 근사(alpha glazing)하고, 주변을 찍은 큐브맵(CubeCamera probe)을 반사에 씁니다.
3. **안티에일리어싱**: 움직이는 동안은 낮은 해상도에 **MSAA 4배**, 멈추면 기기 해상도로 한 번 더 그리고 **FXAA**를 적용합니다.
4. **미리 구운 빛(lightmap bake)**: 1F 카페는 Blender Cycles로 13개 시간대 라이트맵을 구웠고(`new/360/assets/cafe-room-bake/`), 바깥 지면은 하늘 가림(ambient occlusion)을 구웠습니다(`ground-sky-ao.png`). 카페 베이크는 가구 파일 해시로 최신성을 검사하므로 `cafe.js`, `environment.js`를 고치면 다시 구워야 합니다(아래 7장 참고).
5. **실내 간접광(interior fill)**: 위층·지하는 미리 구운 빛이 없어서, TSL 셰이더로 "평면 안쪽 + 층 높이" 영역만 골라 환경광을 줄이고 실내 조명 수준의 간접광을 더합니다(`tools/360/interior-fill.js`).
6. **정밀 이미지**: 버튼을 누를 때만 **경로 추적(path tracing)**(three-gpu-pathtracer 0.0.27, 가속 구조 three-mesh-bvh 0.9.15)과 **노이즈 제거**(Open Image Denoise 웹 버전 oidn-web 0.4.0)로 정지 이미지를 계산합니다.

### 5.3 속도와 끊김 방지

1. **셰이더 사전 준비(shader warm-up)**: WebGPU는 재질마다 셰이더(렌더 파이프라인)를 처음 그릴 때 만드는데, 수천 개를 한 번에 만들면 화면이 수 초 멈춥니다. 그래서 로딩 카드가 떠 있는 동안 물체를 묶음으로 나눠 미리 그리고(정지 화면용 + 그림자), 움직임용은 `compileAsync`로 백그라운드에서 준비합니다. 시안·주차 방식 변경 때도 같은 방식이며, 진행률을 카드에 보여 줍니다.
2. **지연 로드(lazy loading)**: 실내 가구 모델과 카페 라이트맵은 첫 화면 뒤에 받습니다. 사용자가 들어간 층을 먼저, 나머지 층은 카메라가 멈춰 있을 때 하나씩 채웁니다.
3. **용량 줄이기**: 텍스처는 WebP, 3D 모델은 glTF-Transform으로 Draco 압축·면 수 축소, HDR은 1K.
4. **조명 구성 유지**: 조명을 숨겼다 켜면 장면 전체 셰이더가 다시 만들어지므로, 숨기지 않고 세기만 0으로 바꾸거나 기존 조명 객체를 재사용합니다.

### 5.4 원칙

1. 원본 구조(외벽, 기둥, 코어, 슬래브, 개구부)와 원본 조작 의미는 바꾸지 않았습니다. 실사 쪽은 원본을 읽기만 합니다.
2. 무료 자산만 썼습니다(CC0, CC BY, MIT). 유료 스트리밍·도구·에셋은 쓰지 않았습니다.
3. 원본 저장소 `main`과 운영 페이지에는 아무것도 반영하지 않았습니다.

| 차이 | AI 사진보다 식물·소품이 적고, 노출 천장 배관 디테일이 단순합니다. 지하 기둥의 노랑·검정 띠와 실내의 빨간 법규선은 원본 표시라 그대로 보입니다 | 의도된 유지 |
| 차이 | 외장 시안 색은 원본 3D 재질 색을 따릅니다(AI 사진과 다를 수 있음) | Jack 결정 |
| 주의 | 시안을 2～3초 간격으로 연달아 바꾸면 준비가 겹쳐 대기가 길어질 수 있습니다(카드는 계속 표시) | |
| 유지 보수 | `cafe.js`·`environment.js`·카페 가구 파일을 고치면 카페 베이크가 꺼집니다. 테스트 `test-bake-freshness.mjs`가 이를 알려 주며, 다시 굽는 절차는 `docs/360/baked-environment.md`에 있습니다 | 약 3분 |

## 8. 합치기 전 확인과 합치는 방법

### 8.1 무엇을 합칠지 먼저 정해 주세요 (중요)

원본 저장소의 `main`은 그대로 운영 웹사이트(GitHub Pages)로 게시됩니다. 작업 브랜치를 통째로 합치면 작업 기록·도구·증거 이미지까지 공개 주소에 올라갑니다.

| 묶음 | 경로 | 크기(약) | 운영에 필요한가 |
|---|---|---|---|
| 실행 파일 | `new/3d-model.html`, `new/360/` | 78 MB | 필요합니다. 실사 3D가 동작하는 데 쓰입니다(출처 기록 `new/360/assets/README.md` 포함). |
| 작업 기록·증거 | `docs/` | 86 MB | 필요 없습니다. 인계·검토용입니다. |
| 개발 도구·소스 | `tools/360/`(의존성 폴더 제외) | 18 MB | 운영에는 필요 없지만, 렌더러를 다시 고칠 때 필요합니다. |
| 에이전트 안내 | `AGENTS.md`, `CLAUDE.md`, `START_HERE_KO.md` | 작음 | 필요 없습니다. |

**권장안**은 실행 파일만 `main`에 합치고(squash 병합으로 이력을 하나로), 나머지는 작업 브랜치 `codex/tower-360-validation`에 그대로 보관하는 것입니다. 이어서 개발할 때는 작업 브랜치에서 하고, 다시 실행 파일만 옮기면 됩니다. 아래 프롬프트 B가 이 방식입니다.

### 8.2 Wing님이 직접 하실 일

1. 3장의 순서대로 미리보기를 확인합니다. 필요하면 프롬프트 A로 점검을 먼저 시킵니다.
2. 괜찮으면 프롬프트 B를 Claude Code(또는 Codex)에 입력해 PR을 만듭니다. 합치기(merge)는 PR 화면에서 Wing님이 직접 누릅니다.
3. 합친 뒤 운영 페이지(https://wing-kim.github.io/all/new/3d-model.html)에서 '실사 3D'와 원본 보기 방식이 모두 정상인지 확인합니다.

### 8.3 프롬프트 A: 먼저 점검만 시키고 싶을 때

저장소 `wing-kim/all`을 연 상태에서 그대로 붙여 넣으시면 됩니다.

```
wing-kim/all 저장소의 브랜치 codex/tower-360-validation 을 점검해 줘. 코드는 고치지 말고 보고만 해 줘.
1) git fetch 후 이 브랜치와 main 의 차이를 요약하고, main 에 이미 있는 내용과 충돌이 없는지 확인해 줘.
2) docs/360/handoff/WING_HANDOFF.md 와 docs/360/WORK_STATE.md 맨 아래 D-1～D-11 기록을 읽고 무엇이 바뀌었는지 비전공자도 알 수 있게 정리해 줘.
3) tools/360 폴더에서 테스트를 전부 실행해 줘: for t in tools/360/test-*.mjs; do node $t; done (의존성이 없으면 npm --prefix tools/360 ci --ignore-scripts 먼저).
4) 저장소 루트에서 python3 -m http.server 8765 를 띄우고 http://127.0.0.1:8765/new/3d-model.html?lab=review 를 브라우저로 열어 실사 3D 로딩, 시안 변경, 내부 보기 1F～6F, 정밀 이미지, 모바일 폭(375px)을 확인해 줘.
5) 문제가 있으면 무엇이, 어디서, 어떻게 재현되는지 목록으로 알려 줘.
```

### 8.4 프롬프트 B: 확인을 마치고 합칠 때 (실행 파일만, 권장안)

```
wing-kim/all 저장소에 '실사 3D' 기능을 합치려고 해. 작업 브랜치는 codex/tower-360-validation 이고, main 은 운영 GitHub Pages 라서 실행 파일만 합칠 거야.
1) git fetch 후 최신 main 에서 새 브랜치 feature/photoreal-3d 를 만들어 줘.
2) 그 브랜치에 작업 브랜치의 실행 파일만 가져와 줘: git checkout origin/codex/tower-360-validation -- new/3d-model.html new/360
   docs/, tools/, AGENTS.md, CLAUDE.md, START_HERE_KO.md 는 가져오지 마.
3) main 과 비교해 new/3d-model.html 에 바뀐 줄이 실사 3D 연결 부분뿐인지(원본 기능 변경이 없는지) 확인하고 요약해 줘. main 에 그사이 new/3d-model.html 변경이 있었다면 둘 다 살리는 방향으로 합치고 무엇을 합쳤는지 알려 줘.
4) 커밋 메시지는 한국어로 "실사 3D 보기 방식 추가" 로 하고, docs/360/PR_DESCRIPTION.md 와 docs/360/handoff/WING_HANDOFF.md(작업 브랜치에 있음)를 바탕으로 한국어 PR 본문을 만들어 feature/photoreal-3d → main PR 을 열어 줘.
5) 자동 merge 는 하지 마. 내가 PR 화면에서 확인하고 squash merge 할게.
6) 내가 merge 했다고 알려 주면 GitHub Pages 배포가 끝날 때까지 기다렸다가 https://wing-kim.github.io/all/new/3d-model.html 에서 '실사 3D' 로딩, 시안 변경, 원본 보기(스케치업 등)가 정상인지 확인해 줘.
```

### 8.5 프롬프트 C: 합친 뒤 이어서 작업할 때

```
케이프혼타워 3D 모델(wing-kim/all 의 new/3d-model.html)에 들어간 '실사 3D' 보기를 이어서 작업하려고 해.
작업은 브랜치 codex/tower-360-validation 에서 해 줘(문서·도구·렌더러 소스가 여기에 있어). 먼저 git fetch 후 main 의 최신 new/3d-model.html 변경이 있으면 이 브랜치에 반영해 줘.
먼저 docs/360/handoff/WING_HANDOFF.md, docs/360/VIEWER_CONTRACT.md, docs/360/WORK_STATE.md 의 마지막 기록(D-1～D-11)을 읽고 현재 구조를 요약해 줘.
지켜야 할 원칙:
- 원본 건물 구조와 원본 조작은 바꾸지 않는다. 실사 쪽(new/360, tools/360)은 원본을 읽기만 한다.
- 무료 자산만 쓴다(CC0, CC BY, MIT). CC BY 를 쓰면 new/360/assets/README.md 에 출처를 적는다.
- 렌더러 소스는 tools/360 에서 고치고 npm --prefix tools/360 run build 로 new/360/modern.js 를 다시 만든다.
- 고친 뒤 캐시 토큰(new/3d-model.html, new/360/scene.js, new/360/integrated.js 의 버전 문자열)을 함께 올린다.
- cafe.js·environment.js 를 고치면 카페 베이크가 꺼지므로 test-bake-freshness.mjs 결과를 확인하고 필요하면 docs/360/baked-environment.md 절차로 다시 굽는다.
- 끝나면 tools/360/test-*.mjs 전부 통과, 브라우저로 실사 3D 로딩·시안 변경·내부 보기를 확인한 뒤 WORK_STATE.md 에 기록한다.
- 운영 반영은 프롬프트 B와 같은 방식(실행 파일 new/3d-model.html, new/360 만 main 으로 PR)으로 하고, merge 는 내가 직접 한다.
이번에 할 일: (여기에 하고 싶은 작업을 적어 주세요. 예: 7층 시안 실내 추가, 옥상 정원을 AI 사진에 맞추기)
```
