1. 사용자 목표와 완료의 의미

목표는 기존 2D 실사 이미지에서 느끼던 건축·인테리어의 현실감을 연속적인 3D 자유 시점에서 체험하는 것이다. 건축 의사결정용이므로 평면·기둥·창호·코어·계단·층고와 시안별 구조는 원본 모델을 따라야 한다. AI 실사는 재질·분위기 참고이며, 서로 다른 사진의 구조 오류를 모델에 복제하지 않는다.

다음 실행은 끝없이 개선하는 연구가 아니라 사용자가 실제 도입 여부를 결정할 수 있는 체험판을 완결하는 작업이다. 최종 작업은 후속 담당자에게 전달할 프롬프트 작성까지 포함한다. 품질 미달을 숨기거나 기술적 동작 성공을 실사 품질 성공으로 보고하지 않는다.

필수 체험 흐름:
- 기존 페이지에서 원본 외관/구조 후보안을 선택하고 연속 360도 회전·확대·축소.
- 1층 카페로 진입하여 눈높이로 둘러보고 창밖·유리·바닥·좌석·카운터·조명을 확인.
- 같은 확정 구조 안에서 최소 2가지 실내 마감/가구 시안을 실제 3D로 비교. 기존 이미지/자료에 근거하며 확정 설계와 제안 시안을 명확히 구분. 기존 6/7 모던·클래식 사진 선택 기능은 보존.
- 원본 실사와 실시간 3D를 나란히 비교하고, Home/버튼으로 외부 복귀.
- 기본 화면은 회전할 때 정밀 샘플 누적을 기다리지 않고 일관된 품질을 제공. 정밀 이미지는 선택 버튼으로 유지.

필수 개선: 카페 자연광·간접광·유리·재질, 명확한 가구/동선 오류, 초기 로딩과 조작 안정성. 기존 외관·주변 환경과 시안 선택은 유지·검증한다.
선택 확장: 카페가 기준에 도달하고 예산이 남으면 6/7층 대표 실내 1곳. 모든 층·모든 인테리어를 새로 제작하는 것은 이번 완료 범위가 아니다. 새 엔진으로 전면 교체하거나 부수 기능을 늘리는 일은 피한다.

2. 사용량 상한 — 최우선 제약

이번 인계 정리 세션: 주간 사용량 97%를 넘기지 않는다. 작성 시작의 실측은 94%였다. 후속 사용자 요청으로 화면 겹침 최소 수정과 UI 통합 우선순위 갱신만 진행했다.
초기화 후 다음 실행: 계정의 해당 주간 사용량 usedPercent가 50%를 넘지 않도록 한다. '현재 수치에 추가 50%포인트'가 아니다. 사용자에게 별도 확인 없이 리셋 크레딧을 사용하거나 유료 서비스를 결제하지 않는다.
새 대화/컨텍스트 초기화와 주간 한도 초기화는 다르다. 시작 시 get_usage_limits로 실제 초기화 여부와 잔량을 확인한다. 아직 기존 94%대 구간이면 50% 예산으로 작업을 시작하지 말고 상황을 알린다. 다른 채팅/서브 에이전트의 사용량도 공유된다고 보고 모니터링한다.

권장 체크포인트(모두 주간 전체 usedPercent 기준, 예측치가 아님):
- 0~5%: 현재 코드·브라우저 재현, 원본 업데이트 확인, 품질/성능 기준과 범위 확정.
- 5~30%: Sol 중심 핵심 구현, Astra가 중요한 시각/구조 판단만 검수.
- 30~40%: 실제 Chrome 비교·통합·속도/입력 검증. 새 대형 접근법/범위 추가 금지.
- 40~45%: 필수 결함 수정, 결과와 한계 확정. 추가 시각 장식은 중단.
- 45~48%: 최종 캡처·커밋·푸시·보고·후속 담당자용 프롬프트 작성까지 완료.
- 48~50%: 계측 지연·마무리용 여유. 새 작업/서브 에이전트를 시작하지 않는다.
단계 시작과 Sol 작업 전후에 사용량을 확인하고, 큰 작업 중에도 주기적으로 확인한다. 시작 수치가 0%가 아니면 그만큼 작업 예산을 줄인다. 퍼센트는 토큰 수와 정확히 대응하지 않으므로 토큰 환산치를 지어내지 않는다.

예산 내 종료는 필수다. 품질 도달을 무조건 보장할 수는 없으므로, 남은 한도가 부족하면 선택 확장을 먼저 제외하고 필수 흐름을 안정화한다. 최종적으로 실사 기준에 미달하면 원인과 실제 체험 결과를 명시하고 사용 판단에 필요한 인계 문서를 완성한다. 미완료를 완료로 둔갑시키지 않는다.

3. Astra·Sol 역할과 권한

사용자가 Astra 설계·검수 / Sol 구현을 명시적으로 승인했다.
- Astra(부모): 범위·품질 기준, 구조 보존 판단, 접근법 선택, 주요 화면 비교, 통합 승인과 최종 인계.
- GPT-6.1 Sol(구현 서브 에이전트): 범위를 제한한 재질/조명/뷰어 코드, 테스트, 성능 계측, 인계 초안.
- 기본은 Sol 1개를 순차 실행한다. 중복 조사/여러 모델의 같은 작업을 피한다.
- Sol에는 전체 대화 대신 이 문서, 필요한 파일, 현재 커밋, 불변 조건, 담당 파일, 테스트와 완료 기준만 전달한다. 모델 지정 시 도구 규칙에 따라 fork_turns=none을 사용한다.
- 같은 파일을 두 에이전트가 동시에 수정하지 않는다. Astra도 Sol 작업 중 같은 브랜치 파일을 무단 수정하지 않는다. 공유 작업 디렉터리 및 Git 상태를 먼저 확인한다.
- Sol은 한 번에 한 작업 묶음만 수행하고 변경/테스트/한계/다음 검수점을 짧게 보고한다. 이후 작업은 Astra가 검수 후 배정한다.
- 모델 전환 자체가 품질이나 일정 성공을 보장하지 않는다. 이미지 증거와 회귀 검증으로 판단한다.
