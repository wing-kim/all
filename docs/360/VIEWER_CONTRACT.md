# 기존 앱과 실사3D의 기능·상태 계약

기준 main:25b111a, 2026-10-16 소스 확인. 아래 상태는 코드 감사 기준이며 브라우저 전체 검증 완료를 뜻하지 않는다. 목표는 동일 버튼/의미/상태 연결이다. 구현 완료와 자산의 고품질 완성을 별도로 기록한다.

## 구현 설계 (아직 구현된 API가 아님)
원본 모델/상태를 단일 기준으로 유지하고 새 실사 모드 전용 adapter를 도입한다. 기존 정상 동작의 재설계나 전면 상태관리 리팩터링은 범위 밖이다. opt-in일 때만 구독/처리하고 해제 시 원상 복구한다. 거대한 원본 파일을 처음부터 재작성하지 않는다.
- 공유 상태 범주: 설계/구조, 층·공간, 카메라·이동모드, 단면·가시성·주석, 태양/조명 조건, 실내 후보, 사진참조, 렌더 품질.
- 각 원본 명령은 공유 상태를 갱신하고 renderer adapter가 소비한다. 원본 DOM click을 서로 재호출하는 임시 연결은 상태 계약으로 점진 교체한다.
- 모드 전환은 renderer만 바꾼다. 현재 iframe 격리는 유지할 수 있으나 parent/child의 독립된 설계·일시 상태를 만들지 않는다.
- 절단/표시는 지오메트리 파괴 없이 원본 clipping/visibility 의미를 전달한다. 정밀 경로도 같은 절단을 따르거나 미지원임을 명시해야 한다.
- 새 fit-out은 floorId/designId/호환 구조 키/asset 상태로 등록한다. detailed/provisional/structure-only는 자산 상태이며 기능 지원과 별개다.
- 베이크 키는 실제 의존 구조·창·가구·조명 조건을 포함한다. 날짜/시간 재생은 매 프레임 건물 재생성 없이 빛/반사/유효성 갱신. 미일치 베이크는 해제하고 기본 실시간 경로 유지.
- 채광 비교에서는 source 태양 방위/고도와 현대 renderer light vector를 검증한다. HDR 태양과 실제 선택 일시가 충돌하면 배경/반사 처리를 수정하며 실제 태양을 사진 구도에 맞춰 돌리지 않는다.

## 필수 회귀 시나리오
1. 구조/층고/창 선택 → 층 선택 → 세 렌더 모드 왕복: 상태·층·카메라·면적 일치.
2. 1F카페와 상세자산 없는 다른 층: 동일 층/공간 UI, 실제 해당 층 구조 표시.
3. 층 단면/두 종단면/윗층투시/치수/라벨: 실사 모드 유지 및 정확한 표시.
4. 같은 구조·카메라·노출에서 봄/겨울 및 오전/오후/사용자 일시: source 태양과 그림자 방향 일치. 하루재생/야간 점검.
5. 창 크기/구조/가구 변경: 해당 지오메트리 반영, 오래된 베이크 제거, 선택한 실내 시안 유지 또는 명시적 비호환 안내.
6. 원본 사진/실사3D/스케치 전환·비교 해제·외부 복귀: 초기화/강제 다른층/무언 전환 없음.
7. 현황/신축/비교, 주변/지하/대지 표시, 캡처, 휠/키보드/모바일 입력 회귀.

합격은 '버튼이 존재함'이 아니라 실제 상태와 화면 결과가 같은 의미로 동작함이다. 예산으로 미완료한 기능은 행별로 공개하고 연결 완료라고 주장하지 않는다.

## 병합 전 비간섭 검증
일반 URL(쿼리 없음)과 원본 스케치/렌더/사진의 주요 시나리오를 main 기준과 비교한다. 새 모드 진입→이탈 반복 후 기존 기능도 다시 확인한다. 이벤트 중복·카메라 소유권·클리핑/라벨·태양 상태·리소스 누수·기존 자산 경로 변경이 없어야 한다. 새 모드 내부의 기능 대응표 검증과 별개로 기록한다. 빌드 산출물과 필요한 최소 hook 외 unrelated diff를 PR에 포함하지 않는다.
