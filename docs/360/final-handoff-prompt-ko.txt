케이프혼타워 실사 3D 모드 후속 개발을 이어 주세요.

이 문서는 후속 담당자가 현재 결과를 평가하고 이어 개발하기 위한 독립 진입 프롬프트입니다. 프로젝트 전체가 완성됐다는 뜻이 아닙니다. 최신 커밋·배포·테스트 상태는 docs/360/WORK_STATE.md 맨 앞 요약과 마지막 체크포인트를 먼저 확인하세요.

1. 작업 위치와 운영 보존
저장소 https://github.com/wing-kim/all, 작업 브랜치 codex/tower-360-validation, draft PR https://github.com/wing-kim/all/pull/1.
원본 운영 https://wing-kim.github.io/all/ 의 main 및 Pages 설정을 바꾸지 마세요. 검토 배포는 별도 private 저장소 evyfjae/kapehorn-3d-preview에서 공개 Pages로 제공합니다.
검토 URL https://evyfjae.github.io/kapehorn-3d-preview/new/3d-model.html?lab=review&view=cafe.
다른 에이전트가 쓰기 중인지 확인하고 미커밋 변경을 보존하세요. 임의 merge/reset/전체 원본 재작성은 하지 마세요.

2. 목적과 기준
기존 건축·인테리어 의사결정 앱에 표현 모드 하나를 추가합니다. 별도 카페 전시 앱이 아닙니다. 원본의 구조·치수·층·코어·계단·창호·설계 후보·채광 조건·사진 비교와 같은 버튼/의미로 연결되어야 합니다.
원본 실사는 AI 이미지 모음이므로 구조가 서로 모순될 수 있습니다. 구조는 기존 모델/도면을 기준으로 하고 실사는 재질·분위기·인테리어 참고로 사용하세요. 확인한 구조와 추정/검토용 가구를 구분하세요.
카메라 회전 후 정밀 누적을 기다리지 않는 기본 화면에서 현실감을 느껴야 합니다. 실내와 외부 거리/주변 환경을 모두 검증하세요. 정밀 렌더 버튼의 한 장 결과를 기본 탐색 품질 성공으로 대신하지 마세요.

3. 필수 진입 문서
AGENTS.md → docs/360/PROJECT_BRIEF.md → VIEWER_CONTRACT.md → WORK_STATE.md.
Claude Code라면 root CLAUDE.md와 docs/360/handoff/claude-code/README.md/PROMPT.md도 참고하세요. 오래된 TXT 재개 문서는 역사이며 최신 md보다 우선하지 않습니다.

4. 현재 기술과 확인할 결과
원본 HTML/Three 모델을 단일 구조 기준으로 읽고 opt-in iframe에서 현대 Three/WebGPU 표현을 생성합니다. tools/360/modern-entry.js가 빌드 원본이며 new/360/modern.js는 산출물입니다. scene.js는 모델/입력 연결, integrated.js는 원본 UI 브리지, environment.js/cafe.js는 추가 자산입니다.
원본 일시/태양 연결, 층/공간/미니맵/라벨/이동의 검증 내역은 WORK_STATE를 보세요. 층 단면은 원본 그룹 가시성을 전달합니다. 전체/상부 종단면과 윗층투시는 별도 미완료입니다.
카페 floor/ceiling의 ambient-only 베이크는 ambientBake=study 시험 옵션입니다. 기본 꺼짐, 구조/가구 해시/수신면 일치 및 야간/단면 조건을 검사합니다. 전체 GI나 정량 조도 분석이 아닙니다. 새 구조나 자산을 넣고 기존 해시를 무조건 갱신하지 말고 새 입력을 추출해 재제작하세요.

5. 남은 우선 과제
- 실제 공개 화면과 원본 기능을 같은 조작으로 비교하고 VIEWER_CONTRACT의 미완료 항목을 재현합니다. 지원하지 않는 기능을 조용히 다른 모드로 바꾸거나 완료로 표시하지 마세요.
- 실내외 대표 구도를 정해 원본 실사/기존 렌더/새 기본 화면을 함께 비교합니다. 유리 반사/투과, 창호, 벽·가구 간접광, 바닥과 조경/주변 건물 디테일을 개선합니다. 모든 시안·모든 면에서 같은 품질이라고 가정하지 마세요.
- 후보별 fit-out 등록과 원본 사진 맥락 연결을 구현합니다. 현재 가구는 검토용 예시이며 원본 실내 후보와 완전히 대응하지 않습니다. 상세 모델이 없는 층도 구조·채광·이동 기능은 유지해야 합니다.
- 초기 다운로드/첫 프레임, 시안 전환, 기본 회전, 정밀 준비 시간을 따로 측정합니다. 기본 회전은 지오메트리/환경 probe/베이크 재계산을 유발하지 않아야 합니다. CPU 제출 시간을 GPU 시간이나 전체 FPS로 오인하지 마세요.
- 원본 일반 URL과 스케치/렌더/실사 사진 모드의 비간섭 회귀, Chrome/모바일 실기기 검증을 보완하세요. 현재 주된 실제 검증 환경은 IAB입니다.

6. 자산과 참고
무료 모델도 공개 웹 배포 허용 라이선스를 확인하고 출처를 남기세요. Poly Haven CC0 모델을 활용했고 출처는 자산 폴더 source.json과 관련 문서에 있습니다. 실척·충돌·동선 검증이 필요합니다.
reference-method-review.md에는 PlayCanvas Sponza 라이트맵 공식 데모를 실제 실행한 근거가 있습니다. 원리는 참고하되 다른 데모 성능을 우리 앱의 보장값으로 인용하지 마세요. 유료 서비스는 별도 승인 없이 사용하지 마세요.

7. 실행과 배포
로컬: 저장소 루트에서 python3 -m http.server 8765 --bind 127.0.0.1.
빌드: npm --prefix tools/360 run build. 의존성이 없으면 tools/360에서 npm ci --ignore-scripts.
테스트는 변경 영역에 해당하는 tools/360/test-*.mjs와 실제 브라우저로 수행하세요.
배포: tools/360/PREVIEW_DEPLOYMENT.md와 package-preview.py. 원본 전체 repo/업무 문서/오프라인 대형 입력을 공개 배포하지 마세요. 허용 목록 패키지만 별도 배포 저장소에 반영하고 HTTPS 화면을 직접 확인하세요.

각 단계 끝에 전체 계획/현재 위치, 목적 적합성, 적용한 레퍼런스와 확인 깊이, 기술·시각 품질 결과, 남은 문제, 자원/계속 판단을 보고하세요. 최종 보고에는 검토 URL, 커밋/PR, 비교 화면, 성능·회귀 결과, 정확한 미완료 목록과 다음 담당자가 바로 실행할 작업을 남기세요.
